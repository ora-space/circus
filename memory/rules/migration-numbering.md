# 迁移合并前按 main 顺延编号

带编号的数据库迁移（例如 cloud 的 `internal/core/migrations/NNNN_*.sql`）在 PR **合并前**按目标分支 main 上的最新编号顺延，使文件名顺序等于合并顺序：

- 不新增与 main 已有迁移同号、或编号小于 main 最新编号的迁移。main 上历史遗留的同号迁移保持原样，不改名。
- 开发期间不预占号段。多个 PR 并行时各自先用临时编号，谁先合并谁占号，后合并的 rebase 后再顺延；堆叠 PR 按合并顺序依次编号。
- 已经合并进 main 的迁移只追加、不改名、不改内容。
- review 和合并带迁移的 PR 时，核对它的编号是否接在当时 main 的最新编号之后；不是就请作者顺延后再合。

为什么：迁移执行器按文件名遍历，执行所有尚未应用的文件，不管编号大小。同号或编号偏小的新迁移，在新建的库里排在中间执行，在已经升级过的库里却最后执行，两种库的执行顺序不同；一旦某个迁移依赖了后面编号改过的表，schema 就会分叉。重编号只会影响跑过 PR 分支的开发库，重建即可。
